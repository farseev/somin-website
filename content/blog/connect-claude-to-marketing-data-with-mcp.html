To connect Claude to marketing data, add a Model Context Protocol (MCP) server as a connector, sign in with an account that sees only the right client workspaces, and decide which tools Claude may run without asking. For an agency the work is mostly judgement, not code: choose the data, scope the access, then test with one read-only question before anything else.

Key takeaways

  • MCP is an open standard that lets Claude read data and call tools in other systems through a server, so nobody has to paste exports into a chat.
  • Expose the data you would put in a strategy deck, such as competitor posts, studies and performance summaries, and keep personal data and spend controls out at the start.
  • Access is controlled in three places: the account you sign in with, the OAuth permissions you grant and Claude's per-tool approval settings.
  • Before connecting, ask who hosts the server, which tools can change data and how you revoke access.
  • Prove the connection with a read-only question, such as which workspaces Claude can see, before you chain skills together.

What is an MCP server, in plain terms?

An MCP server is a program that sits in front of a data source or an app and describes, in a standard format, what an AI application can do there. Claude connects to it, reads what is on offer and calls it when a question needs that data.

The official MCP documentation describes the protocol as an open-source standard for connecting AI applications to external systems, and compares it to a USB-C port for AI. Its architecture overview names three roles: the host (an AI application such as Claude), a client that the host creates for each connection, and the server that provides context.

Servers offer three kinds of capability, and it helps to know them before you approve anything:

  • Tools: functions Claude can call, such as searching posts or creating a report.
  • Resources: data Claude can read, such as a study or a file.
  • Prompts: reusable templates that structure a task.

Servers run on your own machine or remotely over HTTP. Agencies mostly use remote servers hosted by the data vendor; Claude calls these custom connectors, and Anthropic's help centre lists them on the Pro, Max, Team and Enterprise plans.

How do you connect Claude to marketing data, step by step?

Pick the job, pick a server you trust, add it as a connector, sign in with a narrow account, set tool permissions, then test.

  1. Start from the job. Write down the recurring question first, for example "what did this client's three competitors publish last week, and what landed?" It tells you which data you need.
  2. Choose the server. Use a server built and documented by the vendor that holds the data. The help centre is blunt: "Only connect Claude to servers built and hosted by organizations and applications you trust."
  3. Add the connector. On Team and Enterprise plans only Owners can add a custom connector, and each member then connects with their own account. On an individual plan you add it yourself under Customize › Connectors with the server URL.
  4. Sign in with the narrowest account. The account you authenticate with decides what Claude can see. Review the permissions requested at sign-in and deny anything the job does not need.
  5. Set tool permissions. Claude asks before it runs a tool. Choose "Allow always" only for read tools you would let run unsupervised, and switch off tools a conversation does not need.
  6. Test with a read-only question. Ask something whose answer you can check in the source system, and compare the two.

What marketing data should you expose, and what should you keep out?

Expose the data you would put in a strategy deck. Keep out anything you would not email to a freelancer on their first day.

The rule of thumb: start read-only, and add a write tool only when a person has a clear reason to approve its output every time.

Which security questions should you ask before connecting?

Ask who runs the server, what each tool can change, how access is scoped and revoked, and how it treats instructions hidden in data. A vendor that cannot answer these in writing is not ready for client data.

  • Who builds and hosts it? Where is the data processed, and under which contract?
  • What does each tool do? Ask for the list, split into tools that read and tools that create, change or delete. The help centre also warns that server developers can change tool behaviour, so check again after updates.
  • How is access scoped? The MCP authorisation specification builds on OAuth 2.1 and tells clients to request only the scopes they need. The MCP security best practices warn that broad scopes widen the damage a stolen token can do. The specification also forbids passing tokens through to other services.
  • How do we revoke access? You can cut a connection from Claude's connector settings or from the service's own security settings. Know both routes before a staff member leaves.
  • How does it handle prompt injection? Anthropic warns that malicious servers may hide instructions meant to make Claude act in unintended ways. Public posts can carry the same trick, so treat anything a tool returns as data, never as instructions.

How should an agency roll this out across clients?

Run one client, one recurring job and one owner for two weeks, then turn what worked into a template. Rolling out to every account at once multiplies permissions nobody has tested.

  • Separate access by client. A strategist who works on two accounts should sign in with access to two workspaces, not twenty.
  • Write prompts down as skills. A skill makes a junior run the same steps as a senior, for example /marketing-mondays:somin-pulse.
  • Keep a person at the gate. Anything client-facing or that spends money gets human sign-off, the same rule SOMIN's AI agents follow.
  • Measure two numbers. Track time to first draft and reviewer corrections. If corrections do not fall, the data or the prompt is wrong.

FAQ

What is MCP in Claude?

MCP, the Model Context Protocol, is an open standard that lets Claude connect to external data and tools through a server. In Claude, remote MCP servers appear as connectors that you add once and switch on per conversation.

Do I need a developer to connect Claude to marketing data?

Not to use an existing remote server: you add its URL as a connector, or install a plugin that includes it, then sign in. You need a developer only to build your own MCP server for an internal system.

Is it safe to connect Claude to client data?

It can be, if the server comes from a vendor you trust, the account and OAuth scopes are narrow, write tools need approval and you know how to revoke access. Treat everything a tool returns as data, never as instructions.

Does the SOMIN connector work in Claude Code?

Yes. A plugin added in the Claude app syncs to Claude Code on the same account; run /mcp, pick SOMIN and sign in, and the skills appear as /marketing-mondays: commands.
