The SOMIN brand deck skill builds a brand briefing deck for Claude users. With the SOMIN MCP connector, it pulls real ads and social posts from SOMIN (SoMin.ai), the AI marketing-intelligence company run by Somin Pte. Ltd. in Singapore. Without the connector, the model has no access to that data, so it can only write from memory and whatever you paste in.

Key takeaways

  • Without the connector, the skill has no route to ads or social media data. The model cannot look up what a brand or its competitors actually posted.
  • Pasting data into the chat does not fix this at scale. A model can only read what fits in its context window, and large sets of posts do not fit.
  • Even when text fits, a model reading many items at once misses some, counts them loosely and gives different answers on each run.
  • With the connector, the data is searched and counted outside the model, and the model writes about the result.
  • The deck is then traceable to real posts, which a memory-only deck is not.

What is the SOMIN brand deck skill?

It is one of the skills in the Marketing Mondays plugin for Claude. SOMIN lists brand decks among the plugin's skills, next to Pulse reports, competitor content analysis and landscape reports. The skill is a set of written instructions: what slides to build, in what order, and what to check. It does not contain any marketing data. See the Marketing Mondays plugin explained.

What does the SOMIN MCP connector add?

It connects Claude to your SOMIN workspaces through MCP, the Model Context Protocol. Through it, Claude can search and aggregate posts, list profiles and studies, and read insights. The skill supplies the method; the connector supplies the evidence. Setup is in the SOMIN MCP server guide.

What happens to the deck without the connector?

Three things go wrong, and they compound.

1. There is no data to read

A language model has no live view of Instagram, TikTok, Facebook or Meta's ad systems. It learned from text up to its training date. Ask it what a competitor ran last month and it can only guess a plausible answer. Plausible is not the same as true, and the model will not always tell you which one you got.

2. The data cannot all be held in context

Suppose you try to help by exporting posts and pasting them in. A brand briefing may need hundreds or thousands of posts across several brands, platforms and months. A model reads only what fits in its context window, and everything you add pushes other material out or gets cut. Long inputs also cost more and run slower. So the model sees a slice and writes as if it saw everything.

3. What it does read is processed unreliably

Even inside the window, models are weak at exact work over long lists: counting, ranking, finding every match. They tend to attend to the start and end of a long input more than the middle, skip items without saying so, and round numbers into something that sounds right. The same prompt can give a different "top five" on a second run. A deck that changes every time you build it cannot go to a client.

How does the connector change this?

It moves the heavy work out of the model. Searching, filtering and counting posts run as tools against stored data, and return a small, exact result. The model then reads a table of a few rows, not a pile of thousands of posts. That brings four gains:

  • Coverage: every matching post is considered, because the database does the sweep.
  • Accuracy: counts and shares come from the tool, not from the model's estimate.
  • Stability: the same question returns the same numbers. Wording may vary; the figures should not.
  • Traceability: each claim can point back to the posts behind it, so a reader can check it.

Does the connector remove the need for human review?

No. The connector fixes the data problem. It does not make the model's judgement perfect. A person should still read the deck, check the claims that matter and decide what is worth saying to a client. For why models stay variable by design, read why AI agents are unstable and still repeat themselves.

When is the skill alone enough?

If you only need the structure of a brand briefing and you supply a small, clean set of facts yourself, the skill alone can lay out the slides. Once the deck is meant to say what competitors are doing, what content works, or how a brand compares, you need the data behind it.

FAQ

Can I paste my social media export instead of using the connector?

For a handful of posts, yes. For large exports it is unreliable: the file may not fit, and the model may skim or skip items. A tool that counts and filters the data first is safer.

Does the model remember my brand's posts between sessions?

No. It starts each conversation without your data unless something supplies it again. The connector re-reads the stored data each time.

Why does the same deck prompt give different results on each run?

Language models generate text by sampling likely next words, so wording and choices can vary. Numbers drawn from a tool stay fixed, which is why the connector helps.

Does the connector work with ChatGPT as well as Claude?

SOMIN's pages name Claude, Manus and Codex as supported through MCP. Check the MCP server guide for the current list.

Do I need a SOMIN account to use the connector?

Yes. You sign in to SOMIN when you add the connector, and Claude can see the workspaces your account can see. Plans are on the pricing page.
