## 2. How the translation system works

Pages are built in English first (`build.py`), then `i18n.py` localizes the final HTML:
text is split into **segments** (sentences/blocks); each segment is looked up in a translation memory keyed by `sha1(masked English)[:16]`.

- `data/i18n/<seg>.json` — translation memory per language `{key: translation}`. **This is the only thing you edit.**
- `data/i18n/source.json` — `{key: English}` for every segment (regenerated by `scripts/i18n_todo.py`).
- Missing or invalid translation → that segment falls back to English (the build never breaks).

### Placeholders (must be preserved exactly or the line is rejected)
- `<g1>…</g1>` — inline markup (link, bold). Keep every pair, same numbers; you may move a pair to wherever those words fall.
- `<x3/>` — an inline element that stays as is (icon, line break). Keep it.
- `{1}`, `{2}` — numbers (years, counts, dates). Keep each exactly once; may move them.

### What not to translate
Brand/product/company names (SOMIN, SOMONITOR, Marketing Mondays, MindFuse, Claude, MCP, Meta, Google, GWI, Nielsen, Euromonitor, Milieu, client names), people's names, URLs, e-mails, @handles, #hashtags, code, and titles of cited English sources in "Sources" lists. A segment that is only a name or acronym is returned unchanged.

### Style
Natural, plain B2B marketing language for that market; same meaning and facts, nothing added or dropped; headings that are questions stay questions; UI labels stay short; local punctuation. **Use the glossaries** in `docs/i18n-glossary/` (`glossary_G1.md` zh-Hans/zh-Hant/ja/ko, `G2` th/vi/id/ms, `G3` hi/fil/ar/ru, `G4` es/fr/de/pt) so terms like "share of voice", "whitespace", "consumer tension", "persona", "angle" stay consistent with the 7,111 segments already translated.

## 3. Workflow

```bash
python3 build.py                              # English pages must exist in _site/
python3 scripts/i18n_todo.py --write          # writes _i18n_todo/<lang>.tsv = "key<TAB>English", 5,057 lines per language
# translate, producing lines "key<TAB>translation" (one line per segment, no TAB/newline inside)
python3 scripts/i18n_check.py _i18n_todo/<lang>.tsv my_translation.tsv   # 0 missing, 0 problems
python3 scripts/i18n_merge.py <lang> my_translation.tsv                  # validates and merges into data/i18n/<seg>.json
python3 build.py && python3 tests/check_static.py                        # PROBLEMS (0) required
```

Recommended batching (this is what worked): split each language's TSV into chunks of ~300–600 lines (lines are in page order, so neighbours give context), translate one chunk per language per pass, check, merge. Do one language at a time or group by script/family, with the matching glossary open.

Tips learned:
- Long card-list lines (e.g. the partner/tool list on `/about/` style pages) contain many `<gN>` pairs; translate piece by piece and re-run the checker.
- Reuse existing translations for identical sentences (the memory already dedupes by key).
- Arabic: where a number is a `{N}` placeholder, use neutral wording to avoid number-agreement errors.
- French/German: non-breaking space before `: ; ! ? »` and `%` is added by hand in the existing files; keep doing so.
- Do **not** change keys. If English text changes, its key changes and the segment shows up as missing again.

## 4. Publishing (GitHub web UI, as requested)

Previous releases were shipped by uploading split zip parts to the repo root; the workflow `Unpack uploaded source archive` unzips them, commits, and deploys.

1. Zip only changed files: `git add -A -n . | sed "s/^add '\(.*\)'$/\1/" > files.txt && zip -9 src.zip -@ < files.txt` (expect `data/i18n/*.json` ≈ 1–2 MB each, so ~20 MB total).
2. `split -b 8M -d -a 2 src.zip somin-source.zip.part-` (browser upload limit ~10 MB per file).
3. github.com/farseev/somin-website → Add file → Upload files → both parts → commit to `main`.
4. Watch Actions → "Build and deploy to GitHub Pages" (≈ 1.5 min). Static QA fails the deploy on broken links or missing meta.
   If you have normal git access instead, simply commit and push `data/i18n/*.json`.
5. Verify: `curl -s https://somin.ai/ja/blog/<new-slug>/ | head`, check `https://somin.ai/sitemap-ja.xml` grows, and that hreflang appears on the English post.
